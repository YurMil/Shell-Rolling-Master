# Модуль «Эксцентричный конус» (Eccentric / Oblique Cone)

Техническое задание и математическая спецификация нового режима расчёта в
Shell Rolling Master: развёртка, отчёт и 3D STEP для косого (эксцентричного)
усечённого конуса.

Статус: спецификация к реализации (v1). Документ является источником истины
для модуля; при расхождении кода и документа исправляется код либо документ
осознанно версионируется.

---

## 1. Постановка задачи

### 1.1 Что уже есть

| Режим | Развёртка | 3D | Экспорт |
|---|---|---|---|
| `cylinder` | прямоугольник | Three.js меш + STEP (revolve) | DXF, PDF, STEP |
| `cone` (прямой) | кольцевой сектор | Three.js меш + STEP (revolve) | DXF, PDF, STEP |

### 1.2 Что добавляется

Режим `eccentric-cone` — усечённый конус, у которого верхняя и нижняя
окружности лежат в параллельных плоскостях, но их центры смещены на
величину `e` по оси X. Частные случаи, которые обязан корректно
обрабатывать модуль:

* `e = 0` → вырождается в прямой конус (результат обязан совпасть с режимом `cone`);
* `D1 = D2`, `e > 0` → косой цилиндр (наклонный цилиндр, тоже развёртываемый);
* `e = |R1 − R2|` → «конус с вертикальной образующей» (типовой переходник);
* `e > |R1 − R2|` → образующие расходятся в обе стороны от вертикали.

### 1.3 Разбор прототипа (`eccentric_cone_generator.html`)

Прототип задаёт правильную общую идею (триангуляция «пояс из треугольников»),
но для производства даёт систематически заниженную развёртку. Ошибки,
которые модуль обязан устранить:

1. **Хорды вместо дуг.** Длины `dS_bot`, `dS_top` считаются как 3D-хорды
   между соседними точками. Развёртка — изометрия, поэтому длина нижней
   кромки развёртки обязана быть ровно `2πR1`, а не суммой хорд.
   При `N = 30` относительная недостача `≈ (π/N)²/6 = 1.8·10⁻³`, то есть
   при `D1 = 2460` мм — **около 14 мм** по периметру. Это брак.
2. **Толщина.** `calcLine: 'neutral'` вычитает `t` (то есть K-фактор жёстко
   зафиксирован = 0.5), `'inner'` вычитает `2t`. В проекте принята модель
   с K-фактором (`d_n = d − 2t(1−K)` для OD), и режим обязан ей следовать.
3. **Сварочный зазор не учитывается вовсе** — развёртка всегда на полные 360°.
4. **Нет проверки развёртываемости и вырожденных случаев** (`R1 = R2`
   даёт `Math.max(..., 1)`-заглушки, `e` не ограничен).
5. **DXF R12 без единиц и без слоя `0`-совместимых типов линий**; полилинии
   пишутся незамкнутыми, размеры проставляются текстом `TEXT` вместо
   размерных примитивов — для чтения оператором приемлемо, но контур
   развёртки в виде ломаной из 30 отрезков режется лазером «гранями».
6. **Нет 3D и нет STEP.**

Что из прототипа берётся: соответствие точек по одинаковому углу `φ`
(см. § 2.2 — это действительно точные образующие), раскладка «низ/верх +
линии гиба», понятие расположения шва (короткая/длинная образующая).

## 2. Математика

### 2.1 Обозначения

Правая система координат, ось Z — вертикаль.

| Символ | Смысл |
|---|---|
| `D1, R1` | диаметр/радиус **нижней** кромки по срединной (нейтральной) поверхности |
| `D2, R2` | диаметр/радиус **верхней** кромки по срединной поверхности |
| `H` | высота между плоскостями кромок |
| `e` | эксцентриситет — смещение центра верхней окружности вдоль +X |
| `t` | толщина листа |
| `K` | K-фактор (положение нейтрального слоя) |
| `g` | сварочный зазор |
| `φ` | окружной параметр, `φ ∈ [0, 2π)` |

Нижняя кромка: `A(φ) = (R1 cos φ, R1 sin φ, 0)`
Верхняя кромка: `B(φ) = (e + R2 cos φ, R2 sin φ, H)`

`φ = 0` — сторона, в которую смещён верх (короткая образующая при `e > 0`);
`φ = π` — противоположная (длинная) сторона.

### 2.2 Поверхность и её развёртываемость

Линейчатая поверхность образуется отрезками `A(φ) → B(φ)`
(соответствие «одинаковый φ»). Проверка развёртываемости:

```
A'(φ) = (−R1 sin φ,  R1 cos φ, 0)
B'(φ) = (−R2 sin φ,  R2 cos φ, 0) = (R2/R1)·A'(φ)
```

`A'` и `B'` коллинеарны ⇒ `det[A', B', B−A] ≡ 0` ⇒ поверхность
**развёртываема при любых** `R1, R2, e, H`. Касательная плоскость постоянна
вдоль образующей, точная развёртка существует.

Дополнительно, при `R1 ≠ R2` поверхность является настоящим косым конусом с
вершиной

```
k  = R2 / R1
V  = ( e·R1/(R1−R2),  0,  H·R1/(R1−R2) )
```

и `B(φ) = V + k·(A(φ) − V)`, то есть соответствие по одинаковому `φ` — это в
точности гомотетия относительно вершины, а отрезки `A(φ)B(φ)` — настоящие
образующие конуса. Пункт прототипа подтверждён; неверна была только
метрика развёртки, а не топология соответствия.

При `R1 = R2` вершина уходит в бесконечность — это косой цилиндр,
развёртываемый, но формулы «через вершину» вырождаются. Поэтому
используется единый метод § 2.3, не требующий вершины.

### 2.3 Точная развёртка: ОДУ изометрии

Развёртка — изометрия, значит сохраняются длины кривых на поверхности и
углы между ними. Обозначим плоские образы: `a(φ)` — образ нижней кромки,
`b(φ)` — образ верхней, `ê(φ)` — единичный вектор образующей в плоскости,
`ê⊥` — его поворот на +90°.

```
V(φ) = B(φ) − A(φ)          ℓ(φ) = |V(φ)|      (длина образующей, сохраняется)
p(φ) = (A'·V)/ℓ                                 (проекция хода нижней кромки на образующую)
q(φ) = sqrt(R1² − p²)                           (поперечная составляющая, q ≥ 0)
```

Условия изометрии дают замкнутую систему ОДУ:

```
a'(φ) = p(φ)·ê + q(φ)·ê⊥
ê'(φ) = ω(φ)·ê⊥ ,        ω(φ) = q(φ)·(R2 − R1) / (R1·ℓ(φ))
b(φ)  = a(φ) + ℓ(φ)·ê(φ)
```

Вывод `ω`: так как `B' = (R2/R1)A'`, поперечная компонента верхней кромки
равна `(R2/R1)·q`; из `b' = a' + ℓ'ê + ℓê'` и требования `|b'| = R2`
следует `q + ℓω = (R2/R1)q`.

Свойства (используются как автотесты):

* `|a'| = R1` и `|b'| = R2` тождественно ⇒ длина нижней кромки развёртки
  ровно `2πR1`, верхней — `2πR2`. **Систематическая ошибка хорд устранена.**
* `e = 0`: `p ≡ 0`, `q ≡ R1`, `ℓ = √((R2−R1)² + H²)` = const,
  `ω = (R2−R1)/ℓ` = const ⇒ развёртка — кольцевой сектор с
  `ρ_out = R1·ℓ/|R1−R2|` и углом `2π|R1−R2|/ℓ`. Совпадает с формулами
  существующего режима `cone` (`patternRadiusOuter = slant·R_large/(R_large−R_small)`).
* `R1 = R2`: `ω ≡ 0` ⇒ образующие в развёртке параллельны (косой цилиндр),
  `p = −R1·e·sin φ/ℓ`, `q = R1·sqrt(1 − e² sin²φ/ℓ²)`.

**Интегрирование.** Классический RK4 по `φ` с шагом `h = 2π/M`,
`M = 2880` (0.125°). Порядок `O(h⁴)` ⇒ погрешность замыкания ниже 1e-9 мм
на габаритах в метры. Состояние: `(a_x, a_y, ê_x, ê_y)`; после каждого шага
`ê` нормируется (защита от дрейфа). Точки развёртки для вывода
интерполируются не приближённо, а берутся из узлов сетки: сетка вывода
`N_out` (число станций) выбирается делителем `M`.

**Контроль качества** (пишется в отчёт):
`Δ_closure = | Σ|a'|·h − 2πR1 |` и невязка `|b−a| − ℓ` — обе должны быть
< 1e-6 мм; иначе результат помечается как невалидный.

### 2.4 Толщина, нейтральный слой

Используется та же модель, что и в остальном приложении
(`calculateNeutralDiameters`):

```
OD-спецификация:  D_n = D − 2t(1 − K)
ID-спецификация:  D_n = D + 2tK
```

Смещение применяется к `D1` и `D2`; `H` и `e` не меняются.

*Принятое допущение.* Строго нормальный к поверхности эквидистантный сдвиг
изменил бы радиус на `δ/cos α`, где `α(φ)` — местный угол образующей к оси, и
для косого конуса `α` зависит от `φ`, то есть эквидистанта — уже не
эксцентричный конус. Принимается радиальное смещение (как и в режиме
`cone`), погрешность второго порядка: `δ(1/cos α − 1)`, при `α ≤ 20°` это
< 6 % от `δ`, то есть доли миллиметра. В отчёт выводится `α_min/α_max`,
чтобы технолог видел, когда допущение перестаёт быть безобидным
(порог предупреждения `α_max > 30°`).

### 2.5 Сварочный зазор

Зазор `g` вырезается симметрично относительно шва, углом `Δφ`:

```
Δφ = 2g / (R1 + R2)
```

то есть **среднее** снятое по кромкам расстояние равно `g`
(снизу `g·2R1/(R1+R2)`, сверху `g·2R2/(R1+R2)`). Такой выбор сохраняет
кромки шва настоящими образующими, что критично: только тогда шов в DXF,
в 3D-модели и в STEP — одна и та же прямая. Альтернатива «ровно `g` и снизу
и сверху» ломает образующую и в спецификации отвергнута; фактические
значения зазора по обеим кромкам печатаются в отчёте.

Диапазон интегрирования: `φ ∈ [φ_seam + Δφ/2, φ_seam + 2π − Δφ/2]`.

### 2.6 Положение шва

| Опция | `φ_seam` | Смысл |
|---|---|---|
| `short` | `0` при `R2 ≤ R1`, иначе `π` | по короткой образующей |
| `long` | противоположная сторона | по длинной образующей |
| `custom` | `φ_user` | произвольный угол, град. |

Экстремальные образующие всегда лежат при `φ = 0` и `φ = π` (эксцентриситет
направлен по +X), так как горизонтальный вылет образующей равен
`|e + (R2 − R1)·cos φ|`. Какая из них короткая, зависит от знака `R2 − R1`:
смещение и разность радиусов компенсируют друг друга на стороне `φ = 0`
только когда верхняя окружность меньше нижней. Пресеты `short`/`long`
поэтому вычисляются, а не зашиты в константы.

### 2.7 Раскладка заготовки (MBR)

Как и для прямого конуса, вычисляется минимальный описанный прямоугольник
поворотом контура: грубый проход 0…180° с шагом 1°, уточнение ±1° с шагом
0.1° (для косого конуса контур не симметричен, поэтому диапазон 180°, а не
90°). Далее — приведение к альбомной ориентации и припуск `CUT_MARGIN = 10` мм
(единый с существующим модулем).

### 2.8 Прочие вычисляемые величины

* `ℓ_min, ℓ_max` — минимальная/максимальная длина образующей и их `φ`;
* `α(φ) = atan2(sqrt((Δx)² + (Δy)²), H)` — угол образующей к оси; `α_min/α_max`;
* площадь срединной поверхности `S = ∫∫ r dr dφ`, численно — сумма площадей
  плоских трапеций развёртки (развёртка изометрична ⇒ площадь точная);
* масса заготовки `m = S_blank · t · ρ` (ρ по умолчанию 7850 кг/м³, поле ввода);
* положение вершины `V` (если `R1 ≠ R2`) — справочно для контроля.

## 3. Модель данных

```ts
// features/calculator/types.ts

// Перечисления объявляются рантайм-кортежами, а типы выводятся из них: всё,
// что проверяет значение, пришедшее извне (ссылка на конфигурацию), обходит
// кортеж, а не повторяет литералы — новый режим не может остаться забытым
// в чужом списке допустимых значений (§ 4.1).
export const SHAPE_TYPES = ['cylinder', 'cone', 'eccentric-cone'] as const;
export const SPEC_TYPES = ['OD', 'ID'] as const;
export const SEAM_POSITIONS = ['short', 'long', 'custom'] as const;

export type ShapeType = typeof SHAPE_TYPES[number];
export type SpecType = typeof SPEC_TYPES[number];
export type SeamPosition = typeof SEAM_POSITIONS[number];

interface ShellParameters {
    …существующие…
    eccentricity: number;      // e, мм
    seamPosition: SeamPosition;
    seamAngleDeg: number;      // для 'custom'
    stationCount: number;      // число станций (= линий гиба + 1), 8…360
    density: number;           // кг/м³, для массы
    bendDimensionsEnabled: boolean; // простановка размеров хорд между станциями
    bendDimensionOffset: number;    // вынос размерной линии от кромки, мм
}

/** Одна станция разметки. */
export interface EccentricStation {
    index: number;
    phiDeg: number;
    rulingLength: number;      // ℓ(φ_i)
    cumulativeBottom: number;  // нарастающая длина по нижней кромке от шва
    cumulativeTop: number;
    chordBottom: number;       // хорда до следующей станции (мерить рулеткой)
    chordTop: number;
    bottom: Point2D;           // координаты в системе заготовки
    top: Point2D;
}

export interface EccentricDevelopment {
    bottomEdge: Point2D[];     // образ нижней кромки (контур для резки)
    topEdge: Point2D[];
    stations: EccentricStation[];
    rBottom: number;
    rTop: number;
    totalBottomArc: number;    // = R1·(2π − Δφ), точная длина дуги
    totalTopArc: number;
    minRuling: { length: number; phiDeg: number };
    maxRuling: { length: number; phiDeg: number };
    halfAngleMinDeg: number;
    halfAngleMaxDeg: number;
    apex?: { x: number; z: number };
    surfaceArea: number;
    gapBottom: number;         // фактический зазор по нижней кромке
    gapTop: number;
    gapAngleDeg: number;
    seamPhiDeg: number;
    integrationError: number;  // невязка RK4 (шаг против полушага), мм
    warnings: string[];
}
```

`CalculationResult` получает необязательное поле `eccentric?: EccentricDevelopment`
плюс уже существующие `bbox*`, `flatLength/flatWidth`, `patternRotationDeg`,
`bendLines` — они заполняются для нового режима теми же смыслами, поэтому
2D-вид, PDF и DXF переиспользуют общую инфраструктуру раскладки.

Линии гиба: для эксцентричного конуса это **образующие** (радиальные линии
развёртки) на станциях; шаг разметки неравномерный по определению, в отчёт
идёт таблица, а не одно число `bendStep`.

В UI задаётся именно число линий гиба, `stationCount = bendLines + 1`
(крайние станции лежат на швах и в отдельные линии гиба не выводятся).
Тот же параметр задаёт сетку станций таблицы отчёта.

### 4.1. Ссылки на конфигурацию (`shareLink.ts`)

Версия схемы **не меняется**: оболочка сайта сама проставляет `v` в ссылку и
присылает его обратно, поэтому повышение константы сломало бы восстановление.
Новые параметры добавляются как необязательные — ссылка, созданная до
появления режима, просто оставляет для них значения по умолчанию. Модуль
принимает `v ∈ {1, 2}` на будущее.

Разбор и сборка полезной нагрузки переведены на таблицу
`PARAM_APPLIERS: Record<keyof ShellParameters, ParamApplier>`:

* добавление входного параметра **не компилируется**, пока он не заведён в
  таблицу, — список полей больше нельзя забыть обновить;
* допустимые значения перечислений берутся из `SHAPE_TYPES`, `SPEC_TYPES`,
  `SEAM_POSITIONS` (§ 3), а не из рукописных `||`-цепочек.

Именно вторая проблема и была причиной сбоя: ссылка на эксцентричный конус
формировалась полностью, но при разборе `mode` проверялся списком
`'cylinder' | 'cone'` и режим молча откатывался на цилиндр. Порядок применения
— порядок ключей таблицы, `mode` первым: store пересчитывает результат на
каждом сеттере, и остальные значения осмысленны только после выбора формы.

Проверка: `npm run verify:share-link` (полный round-trip, реальная ссылка
с сайта, все значения перечислений, устойчивость к битой нагрузке).

## 5. Экспорт

### 5.1 DXF (1:1, мм)

| Слой | Цвет | Содержимое |
|---|---|---|
| `CONTOUR` | 7 | замкнутый контур развёртки: нижняя кромка, шов, верхняя кромка, шов |
| `BEND` | 1, DASHED | образующие на станциях (без крайних — они в контуре) |
| `MARKS` | 3 | номера станций (TEXT) вдоль нижней кромки |
| `BEND_DIMS` | — | размеры хорд между станциями (по обеим кромкам) и длины швов |
| `SHEET` | 8 | габаритный прямоугольник заготовки (справочно) |

**Размеры.** При включённых линиях гиба доступна опция простановки размеров
(`bendDimensionsEnabled`). Размеры — параллельные (aligned), между соседними
крайними точками линий гиба: по нижней кромке наружу вниз, по верхней —
наружу вверх, плюс длина образующей на каждом из двух швов. Строятся из
примитивов R12 (выносные линии, размерная линия, засечки, центрированный
`TEXT` с кодами 72/11/21) — без блоков и `DIMENSION`, чтобы файл открывался
где угодно. Геометрия размеров считается общим модулем
`utils/aligned-dimension.ts`, который используют и DXF, и SVG-превью, поэтому
на экране и в файле числа и расположение совпадают. Вынос задаётся
параметром `bendDimensionOffset` (по умолчанию 120 мм).

Контур пишется одной замкнутой `POLYLINE`/`VERTEX`/`SEQEND` (R12-совместимо,
как и текущий writer, флаг `70=1`): нижняя кромка → шов → верхняя кромка в
обратном порядке → шов.

Плотность точек контура не привязана к числу станций: развёртка считается на
сетке `stationCount × round(720 / stationCount)` узлов (≈720 на оборот, всегда
кратно числу станций), так что резать можно гладко, а размечать — по 12–36
точкам. Станции при этом всегда попадают точно в узлы сетки.

Имя файла: `eccentric-cone_D{D1}-{D2}_H{H}_e{e}_t{t}.dxf`.

### 5.2 PDF-отчёт

1. Шапка: наименование, дата, версия приложения, ссылка cadautoscript.com.
2. Исходные данные: `D1, D2, H, e, t, K, g`, спецификация OD/ID, шов, число станций.
3. Расчёт: нейтральные диаметры, `ℓ_min/ℓ_max` с углами, `α_min/α_max`,
   длины кромок, площадь, масса, габарит заготовки, фактические зазоры,
   `closureError`.
4. Чертёж развёртки (векторно, как для прямого конуса) с габаритом.
5. **Таблица станций** (основной рабочий инструмент разметчика), колонки:
   `№ | φ° | ℓ_i, мм | ΣL_низ | хорда_низ | ΣL_верх | хорда_верх | X_i | Y_i`
   — с переносом на дополнительные страницы при `stationCount > 24`.
6. Предупреждения (если есть): `α_max > 30°`, `Δφ` съедает > 5° и т. п.

### 5.3 STEP (3D)

Строится в существующем воркере `cad-worker.ts` через replicad.

**Основной случай (`g > 0`) — один линейчатый лофт, без булевых операций.**
На нижней и верхней плоскостях строится замкнутый контур *кольцевого сектора*
от `φ_start` до `φ_end` (те же углы, что и у развёртки): две дуги по наружному
радиусу, радиальный отрезок, две дуги по внутреннему радиусу, радиальный
отрезок. Контуры имеют одинаковую структуру (6 рёбер) и одинаковые угловые
станции, поэтому `loftWith(..., { ruled: true })` сшивает `φ` с `φ` — это
ровно те образующие, по которым построены развёртка и 3D-превью.

Преимущества по сравнению с «полный лофт + резак»:

* швы тела — это радиальные грани лофта, они **точно содержат образующие шва**,
  и зазор сужается/расширяется от нижней кромки к верхней в точности так же,
  как в развёртке (никакого рассогласования DXF ↔ STEP);
* нет булевых операций, нет совпадающих граней — устойчивее в OCCT;
* дуги остаются настоящими дугами, боковая поверхность не фасетируется.

**Случай `g = 0`** (замкнутая обечайка): кольцо нельзя описать одним контуром,
поэтому строятся два лофта по полным окружностям (`sketchCircle` в плоскости XY
с центрами `[0,0,−H/2]` и `[e,0,+H/2]`) и внутренний вычитается из наружного.

Толщина стенки задаётся радиальным смещением (`R ± δ`) — согласовано с
режимами `cylinder`/`cone` и с § 2.4.

### 5.4 3D-превью (Three.js)

`buildEccentricConeGeometry` строит меш напрямую по образующим: два кольца
вершин (наружное/внутреннее) × два уровня (низ/верх), сегментация 128,
угловой диапазон обрезан на `Δφ` (виден шов), торцы шва закрыты. Нормали —
`computeVertexNormals()`. Полностью аналогично `buildShellGeometry`, но с
эксцентриситетом верхнего кольца.

## 6. Валидация ввода

| Проверка | Сообщение |
|---|---|
| `D1, D2, H, t > 0`, `0 < K ≤ 1`, `g ≥ 0` | как в базовой валидации |
| `t < R1_n` и `t < R2_n` | толщина больше радиуса |
| `\|D1 − D2\| < 1e-6` и `e = 0` | «Это цилиндр — используйте режим Cylinder» |
| `e < 0` | нормализуется: `e → \|e\|` (симметрия) |
| `Δφ ≥ 2π` | «Зазор слишком велик для этой геометрии» |
| `α_max > 30°` | предупреждение (не блокирует) |
| `stationCount` вне 8…360 | клампится |

При `e = 0` расчёт не запрещается: модуль вернёт корректный сектор,
совпадающий с режимом `cone` (это же используется как автотест).

## 7. Проверка

Автотест: `tools/verify-eccentric-cone.ts`, запуск

```bash
npm run verify:eccentric
```

Числовые сверки (сравнение с независимо известными величинами) и фактически
достигнутая точность:

1. **e = 0, D1=2000, D2=1500, H=2500** — радиусы сектора и угол развёртки
   совпадают с `calculateCone`; фактически расхождение 1.8e-12 мм и 7e-15°.
   Дополнительно: все узлы обеих кромок лежат на окружностях с общим центром
   (отклонение < 1.1e-11 мм) — то есть развёртка действительно сектор.
2. **D1 = D2 = 1000, e = 300, H = 1000** — косой цилиндр: длина нижней кромки
   ровно `2π·500 = 3141.5923` мм; все образующие равны
   `√(300² + 1000²) = 1044.0307` мм; образующие развёртки параллельны
   (отклонение 6e-14). Площадь сверена с независимым эллиптическим
   интегралом (периметр прямого сечения × образующая): совпадение 5e-8 мм².
3. **Изометрия (D=2460/1360, H=1470, e=550, t=20, K=0.44):** длины кромок
   развёртки равны `2πR` бит-в-бит; ломаная по 720 узлам короче дуги на
   0.0037 мм (низ) и 0.0020 мм (верх) — то есть контур DXF воспроизводит
   дугу с точностью ~4 мкм на 7.6 м периметра. Для сравнения, хордовая
   схема прототипа при N = 30 даёт недостачу ≈ 14 мм.
4. **Длины образующих:** плоское расстояние `|b_i − a_i|` совпадает с 3D-длиной
   образующей (9e-13 мм). Невязка RK4 (шаг/полушаг) — 2.9e-11 мм.
5. **Зазор:** среднее снятое по кромкам расстояние равно `g` точно;
   кромки укорочены на `Δφ·R` каждая.
6. **Шов:** пресеты `short`/`long` попадают в минимальную/максимальную
   образующую при обоих знаках `R2 − R1`.
7. **STEP** (проверено в браузере на replicad/OCCT): тело — `Solid` из 8 граней
   (наружная и внутренняя поверхности по 2 грани, 2 грани шва, 2 торца);
   объём 174 728 533 мм³ против аналитического 174 729 438 мм³
   (сечение косого конуса горизонтальной плоскостью — кольцо радиусов
   `(1−u)R_низ + u·R_верх`, что даёт точный интеграл) — расхождение 5e-6
   отн., в пределах точности численного интегрирования OCCT.
   Вариант `g = 0` даёт 4 грани и такое же согласие по объёму.
